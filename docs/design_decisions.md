# Design Decisions

本文件记录经过产品和业务规则评审后主动保留的设计边界。它不是 Open Issues 列表：Open Issues 表示未来需要修复的问题；Design Decisions 表示当前有意识接受的产品或业务规则选择。

## Decision-001

标题：Case8：客户认可方案不等于明确进入方案验证

背景：Case8 中客户表示“产品方案本身客户仍表示认可”。讨论点是该表达是否足以判定为 S2 方案验证。

最终决定：当前不把“认可方案”单独视为进入 S2。

原因：题目定义 S2 要求客户明确同意演示、Demo、试用、技术交流或方案评估。“认可方案”属于积极反馈，但不足以证明客户已经明确同意进入方案验证动作。

影响范围：Rule Engine 不扩大 solution_evaluation 的业务边界；Case8 保持当前结果，不因“方案认可”自动保留 S2。

后续是否需要重新评估：如果官方题目定义或更多 Golden Case 明确要求把“方案认可”视为方案验证，再重新评估。

## Decision-002

标题：Case5：“需求继续推进”暂不进入 customer_needs

背景：Case5 中“客户确认需求继续推进”没有进入 customer_needs。讨论点是它是否应作为客户需求字段。

最终决定：暂不修改 Schema 和 Prompt，不把“需求继续推进”直接作为 customer_needs。

原因：当前 customer_needs 更强调具体业务问题、痛点、改善目标或能力需求。“需求继续推进”更接近需求状态，不是具体需求内容。

影响范围：Case5 customer_needs 语义边界继续作为待定 P1，不在本轮修复。

后续是否需要重新评估：如果更多真实样本显示“需求状态”需要单独进入 CRM 字段，再统一评估是否增加字段或调整 customer_needs 语义。
